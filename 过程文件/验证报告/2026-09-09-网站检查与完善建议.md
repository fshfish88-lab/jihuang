# 火堆边百科：网站检查与完善建议

检查日期：2026-09-09。状态：检查完成，存在待完善项。

## 结论与范围

保留现有荒野手记视觉风格。网站已具备可用的攻略与百科框架，下一轮优先解决搜索、列表查找和主线清单覆盖，再增加内容深度与实用工具。

本轮检查源码、现有测试与 `成品文件/github-pages` 的静态成品，未修改网站源码、内容或发布配置，未发布。浏览器使用本机 Chrome 152，通过 Playwright 创建隔离上下文；进度勾选不影响用户日常浏览器。

线上状态未确认：公开 URL 的 Web 读取未成功，浏览器请求遭遇网络访问限制；GitHub Pages API 返回 404。上述证据不足以断言网站未部署或已下线。

## 优先处理

### P1：搜索命中与返回状态

已复现：

- 首页搜索提示包含“怎么复活”，实际输入该词结果为 0；缩短成“复活”则有 5 条相关结果，包括告密的心、试金石、重生护符。
- 搜索“料理”只显示 12 条，页面没有继续加载入口；百科分类实际有 50 道料理。当前显示数字是截断后的结果数。
- 搜索后打开详情再按浏览器返回，关键词清空，结果变回热门推荐。
- 百科筛选“料理”后打开详情再返回，筛选恢复为“全部”，328 张卡片重新出现。补测已等待渲染完成，排除过渡帧误判。

建议：补充自然问句映射；优先匹配名称和明确别名；提供结果总数与加载更多；将关键词、分类写入 URL 并恢复返回位置。让首页所有示例词成为实际浏览器验收用例。

代码定位：`app/composables/useSearchIndex.ts`、`app/pages/search.vue`、`app/components/GuideIndex.vue`。

证据：[零结果](2026-09-09-site-audit/screenshots/search-revive-empty.png)、[返回后关键词丢失](2026-09-09-site-audit/screenshots/search-back-empty.png)、[料理筛选](2026-09-09-site-audit/screenshots/filter-dishes-before.png)、[返回后恢复全部](2026-09-09-site-audit/screenshots/filter-dishes-back.png)。

### P1：百科列表需要适应现在的内容规模

百科索引一次渲染 328 张大卡片。实际页面高度：桌面约 44,912px，375px 手机约 129,018px，相当于约 159 个 812px 高的视口。手机首屏仅露出第一张卡片的一部分。这是查找效率问题，不代表已经测得加载卡顿。

建议：百科使用紧凑图标列表或更小卡片，增加页内搜索、分类与阶段组合筛选；分页或按需加载；筛选显示当前匹配数量。当前筛选料理后仍显示“共 328 份手记”，可改成“料理 50 / 全部 328”。攻略卡片可以继续保留现有视觉形式。

证据：[手机百科](2026-09-09-site-audit/screenshots/375-_wiki.png)、`results.json` 中 `/wiki` 高度、`followup-results.json` 中筛选返回结果。

### P1：主线清单没有跟上攻略扩充

世界路线索引已有 9 篇路线攻略，但可勾选清单仅覆盖基础生存、洞穴遗迹、月岛天体三组，共 13 个节点。最后一个节点仍是带回月岛材料，现有天体、裂隙、织影者及圣所内容没有对应清单节点。

建议：将已有进阶攻略拆成可勾选节点，注明推荐前置、准备材料和完成标志；按路线展示完成度，支持玩家选择当前推进方向。后续可增加进度导出导入与多个世界存档。

代码定位：`app/data/progression.ts`、`app/pages/tools/progression-checklist.vue`。数量以 `followup-results.json` 实测为准。

## 随后完善

### P2：角色与 Boss 攻略要增加可执行细节

角色栏目只有威尔逊、温蒂、沃尔夫冈、薇格弗德、WX-78 五篇；Boss 专栏只有巨鹿、熊獾、蜂后、克劳斯、远古守护者五篇。百科中已有更多 Boss 战斗档案，但没有统一呈现在 Boss 专栏。

深度抽查：威尔逊正文提及技能方向，尚无具体技能选择；巨鹿正文写“多顶头盔、恢复料理”，掉落段写“关键掉落”，却没有直接给出可点击的眼球或眼球伞。现有正确的概括可以保留，再补明确装备清单、恢复目标、攻击节奏示意和掉落用途链接。涉及数量与版本机制时应先核对来源，不直接凭经验填数值。

建议优先统一 Boss 专栏与百科的发现入口，补齐已收录 Boss 的目录；再按用户需求扩充角色，并把“最低准备”和“推荐准备”做成可勾选清单。

### P2：手机阅读更快到达答案

现有详情排版清晰，但手机端波兰水饺的配方区从页面约 914px 才开始；图标、标题、档案编号和属性占据较长顶部区域。长攻略侧栏主要是“相关手记”，没有章节目录。

建议：增加“配方 / 获取 / 用途 / 战斗 / 来源”页内跳转；手机压缩档案首屏；长攻略提供可折叠目录和返回顶部。保留纸张配色、标题字体与图标风格。

证据：[料理首屏](2026-09-09-site-audit/screenshots/375-_wiki_pierogi.png)、[圣所攻略](2026-09-09-site-audit/screenshots/1440-_progression_shadow-sanctum.png)。

### P2：补齐小交互与可访问性

- 导航显示 `/` 快捷键，但按键后仍停留首页，没有触发搜索。
- 手机隐藏“搜索攻略”文字后，按钮只剩 `/`，无障碍树中的链接名称也只有 `/`；应使用放大镜与明确的搜索标签。
- 手机展开菜单后 Escape 不关闭，可补充关闭键与焦点处理。
- 百科详情内部还有一个 `main`，与外层主内容区形成两个嵌套主区域，建议内部改为普通容器。
- 不存在页面使用 Nuxt 默认英文错误页，视觉与中文站点不一致；可提供中文说明、搜索与常用入口。

证据：`results.json` 的 `slashShortcut`、`mobileSearch`、`mobileMenuEscape`、`mainCount`，以及 [404 页面](2026-09-09-site-audit/screenshots/mobile-404.png)。

### P2：来源、版本与分享信息

百科页已有来源链接和核对日期，是应保留的基础。攻略来源不统一，例如圣所正文的来源仅为文字列举，实测正文外部链接为 0；抽查角色与巨鹿正文没有对应的来源列表。

建议：统一攻略来源字段，提供可点击的具体条目或更新说明、核对日期，并区分“本站内容版本”和“游戏更新版本”；增加纠错入口与更新记录。

技术检查发现抽样页没有 canonical，首页没有分享图，详情分享图是站内相对路径，当前没有 sitemap.xml。建议完善绝对地址的 canonical、分享图和站点地图。未检验搜索引擎实际收录，不能将这些缺项表述为已经造成收录失败。

### P2：修好可重复验收与预览入口

1. `test:e2e` 当前不可用：缺少浏览器测试目录限定，错误执行 Vitest 文件。应设置独立 Playwright 配置，并固化搜索返回、分类返回、进度保存及手机导航等关键流程。
2. `preview:static` 指向旧 `.output/public`，其中世界路线仅 3 条；成品目录有 9 条。本轮最终浏览器报告针对成品目录。建议预览启动时显示目标目录、构建版本并校验完整性，或提供明确的成品预览入口。
3. 成品清单记录 1,134 个文件，其中 705 个逐字节一致、429 个原始哈希不匹配。进一步核对发现 429 个全部仅为 CRLF/LF 换行差异，没有其他字节差异。`core.autocrlf=true` 与 `git ls-files --eol` 相互印证。建议为成品设置明确 Git 换行规则，保留清单原始字节一致性；不要放宽验证器来掩盖差异。

证据：`manifest-check.json`；本轮 `test:e2e -- --list` 的错误为 `Vitest failed to find the current suite` / `Cannot read properties of undefined (reading 'config')`，最后 `Total: 0 tests in 0 files`。

## 后续功能取舍

完成上述问题后，优先考虑料理按回血、回理智和食材筛选，以及出行/Boss 物资清单。这两项能直接利用现有结构化资料。再考虑四格锅配方模拟、多世界进度管理、收藏与离线阅读；这些属于新增功能，不是当前故障。

建议实施顺序：搜索与状态保留 → 紧凑百科与手机目录 → 主线清单覆盖 → 攻略深度与来源 → 实用工具。浏览器回归配置、成品预览与换行规则可在第一轮修复时一并整理。
